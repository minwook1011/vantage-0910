## 2. 한 건씩 읽기
- 재료: `docs/data/jp/reports/<rid>.json`
  - `qs`: 최근 8개 분기(백만엔, `cq` = 달력 분기 라벨, `yoy`/`qoq` %) · `ann`: 연간 실적과 회사 예상(`est: true`)
  - `rec`: 가이던스 대비(`beat`)·진척률(`progress`)·가이던스 수정(`revision`)·다음 기 예상(`next_guide`)·EPS 컨센서스(`cons`)·주가 반응(`px`)
  - `docs`: 결산단신(`tanshin`)·설명자료(`deck`) PDF 링크
- **결산단신 PDF를 반드시 읽는다.** WebFetch는 일본어 PDF를 못 읽으므로 내려받아 pypdf로 텍스트를 뽑는다:
  ```bash
  pip install -q pypdf
  curl -s -A "Mozilla/5.0" -o /tmp/t.pdf "<docs[].url>"
  python -c "from pypdf import PdfReader; r=PdfReader('/tmp/t.pdf'); print('\n'.join(p.extract_text() for p in r.pages[:8]))"
  ```
  **앞 8쪽만이 아니라 끝까지 읽는다**(`r.pages` 전체) — 표지 요약표, 「経営成績等の概況」(실적 개요), 재정상태·현금흐름, 통기 예상, 세그먼트 정보, 주석(회계기준 변경·자사주·후속 사건)까지. 설명자료(`deck`)가 있으면 그것도 읽는다.
- 분기 역산용으로 **직전 분기 결산단신**도 같은 방법으로 읽는다(카부탄 개시 목록 `https://kabutan.jp/stock/news?code=<code>&nmode=3`).
- 완성 예시: `docs/data/jp/reports/notes/8227-202702-2Q.json` (시마무라 — 누계에서 분기 역산), `7974-202703-1Q.json` (닌텐도), `1301-202703-1Q.json` (교쿠요)

## 2-0. 회사가 밝힌 구체 내용 뽑기 (필수 — 2026-10-14 사용자: "회사가 실적발표에서 밝힌 구체적인 내용이 왜 없나, 더 자세하게")
숫자 해석만 쓰지 말고 **회사가 이번 발표에서 말한 사실을 빠짐없이** 모은다. 읽는 순서와 우선순위:
1. **결산 설명자료(決算説明資料·決算補足資料)** — 있으면 가장 먼저, 끝까지 읽는다. 사업부·채널·지역별 숫자, 기존점·객수·객단가, 출점·폐점, 가격 정책, 신상품·신업태, 설비 투자, 하반기 계획, 주주환원 방침이 여기 있다. 찾을 곳: `docs[].kind == "deck"`, TDnet 같은 날 공시(`jp_tdnet` 도구, 키워드 「説明資料」「補足資料」), 회사 IR 페이지(결산 자료실). **결산단신보다 설명자료를 더 신경 써서 분석한다.**
2. **결산단신 첨부의 「経営成績等の概況」·세그먼트 설명** — 사업부마다 회사가 쓴 문장(무엇이 늘고 줄었나, 채널, 상품, 원가, 가격 인상 날짜)을 하나씩 뽑는다.
3. **같은 분기·발표 무렵 회사 보도자료(ニュースリリース)** — 신상품 출시일, 가격 개정, 제휴·협업, 캠페인, 설비 도입. 회사 IR·보도자료 페이지와 웹 검색(회사명 + 「新商品」「価格改定」「発売」「リリース」).
4. 언론 보도는 보조로만 — 회사 자료로 확인 못 한 것은 "보도 기준, 회사 자료로는 확인 못 함"이라고 밝힌다.
뽑은 내용은 `analysis_md` 의 **"### 3. 회사가 밝힌 사업별 내용"** 에 쓴다(아래 3-2). 항목마다 출처 종류를 괄호로: (설명자료) (결산단신) (회사 보도자료) (보도). 날짜·상품명·브랜드·채널·숫자를 빠뜨리지 않는다.

**결산단신 표지에 「補足説明資料作成の有無：無」(설명자료 안 만듦)이면** `ir_none: "회사가 설명자료를 만들지 않음(결산단신 표지 기준)"` 을 두고 다시 찾지 않는다(회사 IR 페이지에 따로 올리는지만 한 번 확인). 
**설명자료가 아직 안 나왔으면**(일본은 단신보다 며칠 늦게 올리는 회사가 많다): `ir_pending: "YYYY-MM-DD 확인 — 설명자료 아직 없음"` 을 notes 에 두고, **발표 21일 안의 리포트 중 ir_pending 인 것은 실행 때마다 다시 찾는다.** 나오면 끝까지 읽고 `analysis_md` 의 3번 항목을 설명자료 기준으로 고쳐 쓰고 새로 나온 숫자(사업부·채널·기존점 등)를 2·4·5번에도 반영한 뒤 `ir_pending` 을 지우고 `ir_read: "YYYY-MM-DD 설명자료 반영"` 을 남긴다.

## 2-1. 최근 뉴스 찾기 (뭐 하는 기업인가 · 최근 이슈)
- 카부탄 종목 뉴스 `https://kabutan.jp/stock/news?code=<code>` 목록에서 최근 1~2개월 기사 제목을 보고, 중요한 것(실적 반응·증권사 의견 변경·인수합병·신제품·협업·주주환원)은 기사 본문까지 읽는다:
  ```bash
  curl -s -A "Mozilla/5.0" "https://kabutan.jp/stock/news?code=<code>"                # 목록
  curl -s -A "Mozilla/5.0" "https://kabutan.jp/stock/news?code=<code>&b=<기사ID>"     # 본문(<div class="body">)
  ```
- 필요하면 웹 검색(회사명 + 「ニュース」)으로 보충. 출처는 `sources`에 넣는다.

## 2-2. 딥리서치 — 단신 밖 자료로 검증 (필수)
결산단신만 읽고 쓰지 않는다. **단신 이외 출처를 3개 이상** 찾아 읽고, 읽은 것은 전부 `sources`에 넣는다.
- 회사 자료: 결산 설명자료·보충자료, **월차 자료**(소매는 월별 기존점 매출, 게임은 판매 대수 등), 같은 날 낸 다른 공시(가이던스 수정·자사주·배당)
- 기사: 카부탄 결산 속보와 주가 반응 기사, 증권사 의견 변경, 경제지 기사(웹 검색: 회사명 + 「決算」「月次」「業績」)
- 업계·경쟁사: 같은 시기에 실적을 낸 동종 기업 2~3곳의 매출·이익 증감률, 월별 기존점 매출, 업계 통계·원재료 시세 등 공개 지표
- 쓰는 법: 회사가 든 이유를 **바깥 자료로 맞는지 확인**한다(예: "날씨 탓" → 같은 달 경쟁사 기존점도 나빴나). 확인이 안 되면 "확인 못 함"이라고 쓴다.

## 2-3. 질의응답 (`qa`) — 2026-10-07 사용자 요청: 실적 리포트에 질의응답 내용을 다 넣을 것
- 찾을 곳: 회사 IR 페이지의 「決算説明会 質疑応答」「質疑応答要旨」「主な質疑応答」「Q&A」, 설명회 동영상·로그(書き起こし), 「決算説明会資料」 끝의 Q&A 쪽, 스몰미팅 요지. 웹 검색: 회사명 + 「質疑応答」 + 분기(예: 2027年5月期 第1四半期).
- 일본 기업은 설명회 뒤 **1~3주 안에** 요지를 올리고, 1·3분기에는 설명회를 안 여는 곳이 많다. 리포트를 처음 쓸 때 없으면 `qa: {"items": [], "note": "아직 회사가 공개한 질의응답 없음(YYYY-MM-DD 확인)"}` 으로 두고, **발표 21일 안의 리포트 중 qa 가 빈 것은 실행 때마다 다시 찾는다**(찾으면 qa 만 채워 다시 저장). 21일이 지나도 없으면 note 를 "이번 분기는 질의응답 공개 없음"으로.
- 쓰는 법: **나온 문답을 빠짐없이**(보통 5~20개) 차례대로. 질문 1문장, 답 2~4문장을 **우리말로 줄여 다시 쓴다**(문장 번역·통째 옮기기 금지, 직접 인용 없음). 숫자·기간·브랜드·전망은 빠뜨리지 않는다. 주제가 이어지면 `topic`(예: "기존점 매출", "가격 인상", "출점")을 붙인다.
- 형식: `"qa": {"src": "결산 설명회 질의응답 요지(회사 공개)", "date": "YYYY-MM-DD", "url": "원문 주소", "items": [{"topic": "…", "q": "…", "a": "…"}], "note": "(선택) 한 줄 설명"}`. 읽은 자료는 `sources` 에도 넣는다.
- 질의응답에서 나온 새 사실(회사 전망·숫자)은 `analysis_md` 해당 항목에도 반영한다.

### 3-0. 문체 — 읽기 쉽게 (2026-10-07 사용자: "사실·왜·그래서 꼬리표가 가독성 떨어지고 AI 같다")
요약(`headline`·`summary_md`)·분석(`analysis_md`)·이슈(`issues`)·질의응답(`qa`)에 모두 적용한다. **증권사 리포트를 잘 읽히게 풀어 쓴 신문 기사**처럼 쓴다.
- **꼬리표 금지**: "사실:", "왜:", "그래서:", "배경:", "영향:", "시사점:" 같은 머리말을 붙이지 않는다. 무슨 일 → 왜 → 무슨 의미인지를 **문장 흐름**으로 잇는다.
- **결론을 먼저**: 포인트마다 첫 줄은 무슨 일이 있었는지 말하는 **완결된 문장**을 굵게(예: `**② 매출은 뛰었는데 이익률은 그대로다.**`). 명사 나열식 제목(예: "이익률은 제자리")은 쓰지 않는다.
- **한 문장에 한 가지**: 한 문장은 60자 안팎. 길어지면 끊는다. 한 문장에 숫자는 2~3개까지, 괄호는 하나까지. 괄호 안에 숫자를 또 나열하지 않는다. 숫자가 많으면 표로 뺀다.
- **문단을 나눈다**: 핵심 포인트는 굵은 첫 줄 아래 빈 줄을 두고 2~3개의 짧은 문단(무슨 일 / 회사 설명과 바깥 자료 확인 / 앞으로의 의미)으로. 글머리표(-) 한 줄에 다 밀어 넣지 않는다.
- **영어·전문 약어를 풀어 쓴다**: core → 일회성 제외, GAAP → 회계 기준, YoY → 전년 대비, QoQ → 직전 분기 대비, guidance → 회사 전망, hyperscaler → 대형 클라우드 기업, ramp → 생산 확대, FCF → 잉여현금흐름, SG&A → 판관비. 꼭 필요하면 처음 한 번만 괄호로 원어. 회사·제품 이름은 미국은 영어 그대로, 일본은 한국어 발음.
- **주어를 밝힌다**: "회사는 …라고 설명했다", "시장 예상은 …였다", "폭스콘 매출도 …". 누가 한 말인지 흐리지 않는다.
- **AI 말투 금지**: "주목할 만하다", "시사한다", "~라는 점에서", "~할 필요가 있다", "핵심은 ~이다", "결론적으로", "~것으로 보인다"(근거 없이), "바깥 자료로도 맞다", "~하는 구조다"(남발), "눈여겨볼 대목" 남발. 쉬운 말로 바로 말한다.
- **확인 못 한 것은 자연스럽게**: "회사는 이유를 밝히지 않았다", "아직 확인하지 못했다".
- **다른 사람 말을 따옴표로 지어내지 않는다**: 콜·기사 내용은 간접화법으로("한 애널리스트는 ~라며 ~냐고 물었다").
- 다 쓰고 나서 소리 내어 읽듯 한 번 더 본다 — 숨이 차는 문장, 괄호가 겹친 문장, 영어 약어가 남은 문장을 고친다.
- 완성 예시: 미국 자빌 `JBL-202608`(요약·분석 전체).
- **`tg5` — 텔레그램 줄글 5줄**(2026-10-07 사용자: "텔레는 한 번에 딱 확인 가능하게"). 재무제표 사진 아래에 그대로 붙는다.
  - 정확히 5개 문장, 한 줄에 한 문장, 한 문장 40자 안팎(길어도 50자). 괄호·영어 약어·출처 꼬리표 없이.
  - 순서: ① 어떤 분기였나 한 문장 → ② 왜 그렇게 됐나 → ③ 아쉬운 점(또는 좋은 점의 한계) → ④ 회사 전망·남은 숙제 → ⑤ 그래서 무엇을 의미하나.
  - 숫자는 한 줄에 하나까지(사진에 숫자가 다 있다). 주가 반응은 쓰지 않는다(알림 윗줄에 따로 나온다).
  - 예시(쿠스리노아오키 `3549-202705-1Q`): "이익률은 그대로인데 점포를 늘려 덩치로 이익을 키운 분기다." / "성장은 새 점포, 인수한 슈퍼마켓, 신선식품에서 나왔다." / "기존 점포는 손님이 줄어 매출이 거의 제자리였다." / "순이익이 36% 늘었지만 세금이 줄어든 덕이 크다." / "인수 자금으로 빚과 이자가 늘어난 점도 봐야 한다."

### 3-4. `verdict` — 실적 평가(필수, 2026-10-11 사용자: "숫자만 나열하면 기준이 없어 잘 나온 건지 못 나온 건지 모르겠다")
리포트 맨 위에 큰 판정 카드로 나가고, 실적 목록·텔레그램 실적서프에도 판정이 붙는다. **읽는 사람이 이 카드만 보고 '잘 나왔다/못 나왔다'를 알 수 있게** 쓴다.
- **grade 5단계**: 서프라이즈 · 양호 · 부합 · 부진 · 쇼크. 아래 기준으로 정하고, 기준과 다르게 정했으면 line 에 이유를 쓴다.
  1. **컨센서스(시장 예상)가 있으면 최우선**(일본: `rec.beat`·도구 `jp_consensus`, 미국: `rec.cons`(EPS)·`docs/earnings_calendar.json` 의 매출 컨센서스). 영업이익(미국은 EPS) 차이: **+10% 이상 서프라이즈 · +3~10% 양호 · ±3% 이내 부합 · −3~−10% 부진 · −10% 이하 쇼크**. 매출은 그 절반 폭(±1.5%·±5%)으로 보조 판단.
  2. **컨센서스가 없으면** 회사 연간 계획 대비 진척률(`rec.progress`: 이번 진척률 vs 같은 분기 5년 평균, diff): **+6%p 이상 서프라이즈 · +2~6 양호 · ±2 부합 · −2~−6 부진 · −6%p 이하 쇼크**. 계획이 없으면 전년 대비 영업이익 증감과 이익률 변화로.
  3. **가이던스**: 연간 계획(미국은 다음 분기·연간 가이던스) 상향이면 한 단계 올리고, 하향이면 한 단계 내린다. 다음 분기 가이던스가 컨센서스보다 낮으면 한 단계 내린다.
  4. **질**: 일회성 이익(자산 매각·환차익·세금)으로 맞췄거나, 이익률·재고·현금흐름이 눈에 띄게 나빠졌으면 한 단계 내린다(line 에 명시).
  5. **주가 반응은 판정에 넣지 않는다** — `market` 에 따로 쓴다(일본 PTS·다음 날, 미국 발표 후). 판정과 방향이 반대면 왜 그런지 한 줄(예: "숫자는 좋았지만 가이던스 유지에 실망").
- **checks 3~5줄**: 매출·영업이익(EPS)·연간 진척률/가이던스·이익률 등 판정에 쓴 항목. `actual`=이번 숫자, `base`=비교 기준(무엇과 비교했는지 이름까지: "컨센서스 48억엔", "5년 평균 진척률 52.7%", "전년 동기 9.1%"), `diff`=차이(+8.3%, −6.0%p), `tone`=up/dn/flat.
- **line**: 결론 한 줄. 예) "영업이익이 컨센서스를 8% 넘었고 연간 계획도 올려 양호 — 다만 매출은 예상 수준". 숫자 기준을 꼭 넣는다.
- **headline·summary_md 첫 줄도 판정과 같은 결론**으로 시작한다(예: "컨센서스 상회(양호) — …").
- **발표 7일 안의 리포트 중 verdict 가 없는 것은 실행 때마다 채운다**(새 리포트를 다 쓴 뒤 남는 시간에, 최근 것부터).

### 3-1. `orig_md` — 원문 정리 (한글)
리포트 맨 아래 「③ 원문」의 접이식 칸 **원문 정리 (한글)** 으로 나온다(그 아래 원문 PDF 링크). 결산단신을 **원문 순서 그대로** 한국어로 정리한다. 제목은 `### 1. …` 형식으로 아래 6개를 고정한다.
1. **표지 요약표** — 연결 경영성적(매출·영업·경상·순이익과 증감률, 포괄이익, 주당순이익), 재정상태(총자산·순자산·자기자본비율), 배당(분기별 실적·예상), 통기 예상(증감률·주당순이익). **표지에 있는 숫자는 전부** 마크다운 표로 옮긴다.
2. **경영성적 개황** — 회사가 설명한 영업 환경, 실적이 움직인 이유, 주요 제품·매장·시책.
3. **세그먼트별 실적** — 세그먼트 표(매출·이익, 전년 대비)를 전부 + 회사 설명 요지.
4. **재정상태·현금흐름** — 자산·부채·순자산의 주요 증감 항목과 금액, 현금흐름표가 있으면 영업·투자·재무 흐름.
5. **통기 예상·수정 여부** — 예상 숫자, 이번에 바꿨는지, 회사가 든 전제.
6. **주석** — 회계기준 변경, 세그먼트 구분 변경, 자사주 취득·소각, 주식 분할, 후속 사건, 연결 범위 변경 등.

쓰는 규칙
- **숫자와 표는 빠짐없이.** 원문 단위(백만엔)를 **억엔**으로 바꿔 쓴다(÷100, 1,000억엔 이상은 정수, 그 아래는 소수 첫째 자리). 주당 값·비율은 원문 그대로. 표는 `| 항목 | … |` + `|---|---:|` 마크다운 표(숫자 열은 `---:`로 오른쪽 정렬). 원문 표가 누계라면 **누계 그대로** 옮기고 표 제목에 기간(예: 3~8월 누계)을 밝힌다 — 이 칸은 원문을 그대로 보여 주는 곳이라 여기서는 누계를 쓴다(단어 `누계` 사용 가능).
- **설명 글은 문장 단위로 번역하지 않는다.** 단락마다 내용을 **자기 말로 줄여 다시 쓴다** — 사실·수치·회사가 든 이유는 하나도 빼지 않되, 원문 문장 구조를 따라가지 않는다. 단락 전체를 그대로 옮긴 번역 금지. 직접 인용은 **15단어 미만, 리포트 한 건에 많아야 1개**. 설명자료 슬라이드 문구도 옮기지 말고 요지만.
- 원문에 없는 내용·해석을 넣지 않는다(해석은 `analysis_md`에). 원문에 해당 항목이 없으면 "원문에 기재 없음".
- 전부 한국어(회사·브랜드·상품 이름도 한국어 발음). 가나·한자 금지.
- 분량 기준: 2,500~5,000자(표 포함). 재무제표 본표 전체를 옮길 필요는 없고 주요 항목만.

### 3-2. `analysis_md` — 딥리서치 분석 (고정 10개 항목)
제목은 아래 그대로 `### 1. 한 줄 결론` … `### 10. 다음 발표 전 체크포인트`(화면의 ①②③ 구획 번호와 섞이지 않게 아라비아 숫자). **4,000~7,000자** — 구체 내용(3번)을 줄이지 않는다.
1. **한 줄 결론** — 이번 분기 3개월 기준으로 무엇이 좋았고 나빴나. 2~3문장.
2. **핵심 포인트** 3~5개 — 각각 **굵은 완결 문장 한 줄**(무슨 일이 있었나) + 빈 줄 + 짧은 문단 2~3개: 원문 숫자 → 회사 설명과 바깥 자료로 확인한 것 → 다음 분기·연간에 미치는 영향. 꼬리표(사실·왜·그래서)는 쓰지 않는다(3-0 문체).
3. **회사가 밝힌 사업별 내용** (2-0) — 사업부·채널별로 회사가 이번 발표에서 말한 사실을 소제목(굵게)과 글머리표로 빠짐없이: 채널 확대(어느 판로에서 늘었나), 신상품(이름·출시일), 가격 개정(날짜·폭·손님 반응), 출점·폐점·업태 전환, 캠페인·협업, 설비 투자, 원가 대응, 하반기 계획, 주주환원. 각 줄 끝에 (설명자료)(결산단신)(회사 보도자료)(보도). 회사가 숫자를 안 밝힌 부분은 "따로 공시 안 함"이라고 적는다. 설명자료가 아직 없으면 마지막 줄에 "설명자료 아직 미공개 — 나오면 보강"이라고 적는다.
4. **세그먼트·사업별 3개월 실적** — 누계에서 역산한 이번 분기 숫자와 전년 같은 분기 대비. 표를 써도 된다.
5. **이익률·비용 구조 변화** — 매출총이익률·판관비율·영업이익률이 전년 같은 분기·직전 분기 대비 어떻게 움직였고 왜인지. 일회성 항목은 따로 떼어 쓴다.
6. **가이던스·컨센서스·진척률** — 연간 계획 대비 어디까지 왔고, **남은 분기에 필요한 숫자**와 그것이 전년 같은 기간 대비 몇 % 증감인지. 컨센서스(`rec.cons`)와 비교.
7. **업계·경쟁사 비교** — 같은 시기 발표한 동종 기업, 월별 기존점 매출·업계 통계 등 공개 지표(웹 검색). 출처를 문장 안에 밝힌다.
8. **주가 반응과 밸류에이션 맥락** — 발표 후 주가(`rec.px`), 시장이 본 포인트(기사), 시가총액 대비 이익 수준(PER·배당수익률 등 계산 가능한 것만).
9. **리스크·반론** — 위 결론이 틀릴 수 있는 이유, 일회성 요인, 회사 설명 중 확인 안 된 것.
10. **다음 발표 전 체크포인트** — 날짜가 있는 확인 거리(월차 발표일, 다음 실적 발표 예정일, 신제품 출시 등).

쓰는 규칙
- **단신 이외 출처 3개 이상**으로 검증하고 전부 `sources`에 넣는다(2-2).
- 출처에 없는 추측 금지. 원인을 모르면 **"단신에 설명 없음"**, 바깥 자료로도 못 찾으면 "확인 못 함".
- 투자 권유 표현 금지(사라·팔아라·목표가 제시·유망하다 등). 사실과 계산만.

공통 규칙
- **전부 한국어로 쓴다. 일본어(가나·한자) 금지** — 회사·브랜드·상품·게임 이름도 한국어 발음이나 통용되는 한국어 이름으로(しまむら→시마무라, アベイル→아베일, 『トモダチコレクション』→『토모다치 컬렉션』). 예외는 `trend_kw`(검색용) 하나뿐.
- **요약·분석은 이번에 발표한 분기 3개월만** — 결산단신은 누계(상반기·3분기 누계)로 나오므로, 사업별 숫자도 `이번 누계 − 직전 분기 누계`로 3개월치를 계산해서 쓴다(전년 같은 분기도 같은 방법: 누계 ÷ (1+YoY)로 전년 누계를 구해 뺀다). 직전 분기 결산단신은 카부탄 개시 목록 `https://kabutan.jp/stock/news?code=<code>&nmode=3`에서 찾는다.
  `headline`·`summary_md`·`analysis_md`·`tg`에는 「상반기」「하반기」「누계」 같은 말을 쓰지 않는다. 연간 계획 대비 진척은 "3~8월 두 분기에 331억엔 → 남은 두 분기에 337억엔 필요"처럼 분기 말로 쓴다. (원문을 옮기는 `orig_md`의 표 제목만 예외.)
- 분기 이름은 사이트 표기(`qs[].cq`, 달력 기준: 3Q26 = 2026년 6~8월 또는 7~9월)를 먼저, 회사 기준(2027년 2월기 2분기)은 괄호로.
- 사이트가 **분기 표(요약 첫머리)와 그래프(분석 첫머리)를 자동으로 그린다** — 요약·분석에서 그 표를 다시 만들지 말고 해석에 집중(세그먼트 표처럼 사이트가 안 그리는 표는 써도 된다).
- 금액은 **억엔**(백만엔 ÷ 100).
- 다 쓴 뒤 스스로 점검: 3번 '회사가 밝힌 사업별 내용'에 설명자료·단신 개황의 구체 사실(상품명·날짜·채널·숫자)이 빠짐없이 들어갔는가 · 설명자료를 읽었는가(없으면 ir_pending) · JSON이 파싱되는가 · `trend_kw` 밖에 가나·한자가 없는가 · 요약·분석에 금지어가 없는가 · `sources`에 단신 외 3개 이상인가 · `orig_md`에 6개 항목과 표가 있는가.
